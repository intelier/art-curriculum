# 과목 파일 작성 지침 — 초등 교육과정 암기장 (art-curriculum)

당신이 만들 것: `C:/Users/stazy/coding/art-curriculum/subjects/<key>.js` 한 파일.
이 파일은 `index.html`이 `<script src>`로 읽으며, 맨 끝에서 `defineSubject({...})`를 한 번 호출해 과목을 등록한다.
**index.html은 절대 건드리지 않는다.** 다른 과목 파일도 건드리지 않는다.

## 원칙 (가장 중요)

1. **고시문 원문은 한 글자도 바꾸지 않는다.** 띄어쓰기, 문장 부호(⋅ 가운뎃점, ‘ ’ 따옴표 등), 오타처럼 보이는 것까지 그대로. PDF에서 줄이 바뀌며 갈라진 낱말만 이어 붙인다(줄 끝이 낱말 중간이면 붙여 쓰고, 낱말 사이면 띄어 쓴다). 점검기가 띄어쓰기를 무시하고 PDF 글과 대조하므로, 글자가 하나라도 다르면 오류가 난다.
2. **초등학교 부분만.** 중학교·고등학교 성취기준, 중학교 내용 요소는 넣지 않는다. 내용 체계표에서도 초등 학년군 열만.
3. 원문이 아닌 글(퀴즈 문제 문장, 외우기 팁, 연상법)은 자유롭게 쓰되, 원문 문장과 섞이지 않게 `lists`·`tips`·`examNote`에만 둔다.
4. 기출 학년도는 **지어내지 않는다.** `hot`은 비워 둔다(`{}`). `examNote`에는 "기출 표시는 아직 없다"고 적고, 이 과목에서 무엇을 중심으로 외우면 좋은지 안내만 한다.

## 자료

- PDF 글: PDF에서 뽑은 글 파일(`node tools/extract-pdf.mjs <pdf> <out.txt>`, pdfjs-dist 필요) (공통 교육과정 부분만 잘라 둔 것. `=== PAGE n ===` 줄은 쪽 경계). 전체는 `<key>.txt`.
- 본보기: `C:/Users/stazy/coding/art-curriculum/subjects/pe.js` (체육과). 다만 체육과는 `doc`을 직접 짜 넣은 옛 방식이다. **당신은 `doc`을 쓰지 말고 아래 구조화된 항목들로만 쓴다** (index.html의 `buildDoc`이 문서를 짜 준다). 본보기에서 볼 것은 `T(문장, [빈칸 후보])` 쓰는 법, `el`·`sb`의 모양, `lists`·`tips`·`ox`의 분위기.
- 공통 틀 설명: index.html 안 `/* ═════════ 과목 공통 틀` 주석(2014행 근처) — `defineSubject`에 넣을 항목 목록.

## 파일 구조

```js
/* <과목명> — 2022 개정 <과목명> 교육과정(교육부 고시 제2022-33호 [별책 N]) 초등학교 관련 부분. 원문은 한 글자도 고치지 않는다. */
const XX_AREAS = [...];            // 내용 체계의 영역 이름 (원문 그대로)
const XX_GRADES = [...];           // 초등 학년군, 예: ["3~4학년", "5~6학년"] 또는 ["1~2학년", "3~4학년", "5~6학년"]
const XX_IDEAS = { 영역: [T(...), ...] };   // 핵심 아이디어
const XX_EL = { 영역: { 학년군: { "지식이해": [...], "과정기능": [...], "가치태도": [...] } } };
const XX_SB = { 학년군: [ { title: "(1) 영역 이름", items: [ ["4국01-01", "문장", ["빈칸 후보", ...], [T(해설 문장, [...])]?], ... ] }, ... ] };
const XX_NOTE = { 학년군: [ ["영역 이름", T(...), T(...)], ... ] };   // 성취기준 적용 시 고려 사항 발췌 (선택)
const XX_OVERVIEW = [ { p: [T, ...] }, { h: "소제목", lab: "개요 · 소제목", p: [T, ...] } ];   // 교육과정 설계의 개요 (선택, 있으면 넣기)
const XX_CHAR = [ [T, T, ...], [T, ...] ];   // 성격 — 문단별로 문장 나눔
const XX_GOAL = { lead: [T(...)], items: [ ["(1)", T(...)], ["(2)", T(...)], ... ] };
const XX_TEACH = [ { h: "(1) 교수⋅학습의 방향", lab: "교수⋅학습 방향", items: [ ["(가) 제목", T, T], ... ] },
                   { h: "(2) 교수⋅학습 방법", lab: "교수⋅학습 방법", items: [ ["(가) 제목", [ ["①", T], ["②", T, T] ]], ... ] } ];
const XX_EVAL = [ ...같은 꼴... ];
const XX_LISTS = [ ... ];          // 목록 쓰기 문제 (아래 설명)
const XX_OX = { ... };             // 틀린 곳 찾기 짝 (아래 설명)
function XX_TIPS() { return tipCard("제목", `html`) + tipCard(...); }
var XX_EXAM_NOTE = `<div class="card tip-card exam"><h2>...</h2><ul><li>...</li></ul></div>`;
defineSubject({
  key: "<key>", name: "국어과", short: "국어", sub: "2022 개정 국어과 교육과정 · 초등학교 1~2학년, 3~4학년, 5~6학년",
  notice: "원문은 2022 개정 국어과 교육과정(교육부 고시 제2022-33호 [별책 5]) 중 초등학교 관련 부분을 그대로 사용했습니다.",
  landing: "설계의 개요 · 성격·목표 · 핵심 아이디어 · 내용 요소 · 성취기준(1~2 · 3~4 · 5~6) · 교수⋅학습·평가",
  color: { light: ["#b42318", "#fdecea", "#f5bdb6"], dark: ["#ff8a7a", "#3a1a17", "#6b2f2a"] },
  title: "2022 개정 국어과 교육과정 빈칸 학습지 (초등학교)", foot: "원문: 2022 개정 국어과 교육과정(교육부 고시 제2022-33호 [별책 5]) 중 초등학교 관련 부분.",
  areas: XX_AREAS, grades: XX_GRADES, overview: XX_OVERVIEW, char: XX_CHAR, goal: XX_GOAL, ideas: XX_IDEAS, el: XX_EL, sb: XX_SB, note: XX_NOTE,
  teach: XX_TEACH, eval: XX_EVAL, lists: XX_LISTS, tips: XX_TIPS, examNote: XX_EXAM_NOTE, ox: XX_OX, hot: {}
});
```

파일 안에서 쓸 수 있는 전역: `T`, `CATS`, `CAT_LABEL`, `esc`, `tipCard`, `defineSubject`. 그 밖의 index.html 함수는 쓰지 않는다. 맨 위 수준에는 `const`/`function`/`var` 선언과 마지막 `defineSubject` 호출만.

### `T(문장, 빈칸후보)`
- 문장 하나에 `T` 하나. 긴 문단은 문장 단위로 나눈다(마침표 기준).
- 빈칸 후보는 **문장 안에 그대로 있는** 2~5글자 이상의 핵심 어구 1~4개. 외워야 할 낱말(개념어, 분류 이름, 숫자, 열거된 항목)을 고른다. 같은 어구가 문장에 두 번 나오면 `"어구@2"`로 두 번째를 가리킨다.
- 빈칸 후보가 없는 `T`는 퀴즈에서 빠진다(원문 읽기에만 나옴). 꼭 외울 필요가 없는 문장은 비워도 된다.

### 넣을 범위와 분량
- `overview` 설계의 개요: 역량·영역 구성·내용 요소 구성처럼 시험에 나올 만한 문단 위주(전부 넣어도 됨).
- `char` 성격: 전부. `goal` 목표: 전부.
- `ideas` 핵심 아이디어: 전부. `el` 내용 요소: 초등 학년군 전부. **열(학년군)을 잘못 나누지 않도록** PDF에서 열이 섞여 추출된 줄(`⋅A ⋅B ⋅C` 한 줄에 3~4개)은 왼쪽부터 학년군 순서다. 지식·이해에 소범주(예: 국어의 "담화 유형", 수학의 하위 영역)가 있으면 소범주 이름은 넣지 말고 항목만 평평하게 넣는다. 성취기준과 대조해 학년군이 맞는지 확인한다. 원문 표에서 어떤 범주(흔히 과정⋅기능·가치⋅태도)가 초등 전체 한 칸이면, 모든 학년군에 같은 목록을 넣고 `defineSubject`에 `elMerged: ["과정기능", "가치태도"]`를 준다(표와 목록 문제에서 한 칸으로 다룬다). 가짜 학년군 열을 만들지 않는다.
- `sb` 성취기준: 초등 전부, 코드 순. 코드는 `"4국01-01"`처럼 ASCII 하이픈. `title`은 원문의 영역/소제목 "(1) 듣기⋅말하기"처럼. 과학·사회처럼 성취기준이 단원별로 묶여 있으면 그 단원 제목을 `title`로.
  - 해설(네 번째 칸)은 **분류·열거·예시·정의가 들어 있는 문장만** 골라 1~2문장(각 `T`) 넣는다. 학년군당 10~20개 정도. 모두 넣지 않는다.
- `note` 고려 사항 발췌: 영역(또는 학년군)마다 2~4문장. 평가 방법·지도 유의점처럼 시험에 나올 법한 것.
- `teach`/`eval`: "(1) 교수⋅학습의 방향", "(2) 교수⋅학습 방법", "(1) 평가의 방향", "(2) 평가 방법"의 **소제목은 전부**, 각 소제목 아래 핵심 문장 1~3개.
- 성취기준이 아주 많은 과목(수학·과학·사회·국어)은 해설·고려 사항을 더 아껴서, 전체 `T` 문장 수가 250~400개 사이가 되게 한다. 작은 과목(도덕·음악·영어·미술·실과)은 150~250개.

### `lists` 목록 쓰기 문제
```js
{ sec: "idea", label: "범위 안 이름표", q: "질문 (…을 모두 쓰세요.)", unit: "영역", answers: ["원문 그대로", ...],
  alias: { "긴 답": ["짧은 답"] },   // 선택
  w: "앞·글·자", tip: "연상법 설명" }   // 선택
```
- `sec`는 범위 키: `over`(개요), `char`, `goal`, `idea`, `content`, `sb0`/`sb1`/`sb2`(학년군 순서대로 0부터), `teach`, `eval`.
- 내용 요소 18~27칸 목록 문제는 **자동으로 만들어지므로 넣지 않는다.** 당신은 그 밖의 묶음을 만든다: 역량, 영역, 하위 분류, 성취기준 해설의 열거 항목, 교수⋅학습 방향 제목, 평가 방향 제목 등 10~25개.
- `answers`는 원문의 표현 그대로(점검기가 원문에 있는지 본다).

### `ox` 틀린 곳 찾기 짝
```js
"문장 안에 그대로 있는 열쇠 어구": [["원문 말", "바꿀 말"], ["원문 말2", "바꿀 말2"]]
```
- 열쇠 어구는 어떤 `T` 문장 하나에 들어 있어야 하고, "원문 말"도 그 문장에 있어야 한다. "바꿀 말"은 시험에 나올 법한 헷갈리는 말(숫자 바꾸기, 비슷한 개념, 반대말, 다른 영역 이름).
- 40~100개. 성격·목표·핵심 아이디어·성취기준·교수학습·평가에 골고루.

### `tips` 외우기 팁
`tipCard(제목, html)`을 이어 붙여 돌려준다. 6~9장: 과목 한눈에(역량·영역·범주), 영역별 핵심 아이디어 요약, 학년군별 내용 요소 비교표(`<table class="num-table">`), 성취기준 코드 읽는 법, 앞글자 연상법, 교수⋅학습·평가 큰 줄기, 숫자/고유 용어 모음. html 안에서 `esc()`를 써서 문자열을 넣는다.

### `examNote`
`<div class="card tip-card exam"><h2>과목명 — 어디를 집중해서 볼까</h2><ul><li>…</li></ul></div>`. 첫 항목에 "기출 표시는 아직 없어요"를 적는다.

## 점검

작성 후 반드시 실행해 **오류 0개**가 될 때까지 고친다:
```
node tools/check.mjs <key> <PDF 글 파일>
```
경고(⚠)는 읽어 보고 뜻이 있으면 고친다(목록 답이 원문에 없다는 경고는 줄임말이면 괜찮음).
점검기는 PDF 글(`<key>_common.txt`)과 대조한다. "원문에 없는 문장" 오류는 거의 전부 전사 실수(띄어쓰기는 무시되니 글자·부호 차이)다. PDF 글을 grep해서 정확한 글자를 확인한다. 가운뎃점은 `⋅`(U+22C5)이 대부분이고 `·`(U+00B7)과 다르니 PDF 글에서 복사한다.
